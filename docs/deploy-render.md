# Deploy on Render (free) + Cloudflare (free)

```
astrq-platform-ui ──tag vX.Y.Z──► GitHub Release (ui-dist.tar.gz)
                                        │ pinned by ui.version
astrq-platform-api ──merge to main──► Image workflow ──► ghcr.io/<org>/astrq-platform-api:sha-…
                                                            │ Deploy Hook (?imgURL=…)
Cloudflare Cron Worker (08:45–15:10 VN, Mon–Fri) ──GET /health──► Render (radar + DNSE)
Browser ─► https://radar.astrq.io.vn ─► Cloudflare (Access + adds X-Astrq-Origin) ─┘   │
                                                     Cloudflare R2 (baselines, signals) ◄┘
```

Why each piece exists:

| Piece | Reason |
|---|---|
| Keep-alive Worker | Render free sleeps after 15 min without *incoming* requests; the outbound DNSE WebSocket does not count. Pinging only in trading hours = runs 09:00–15:00 Mon–Fri and sleeps otherwise (~140 of the 750 free hours/month). |
| R2 | Render free has no persistent disk; daily baseline summaries and today's signals would be lost at every sleep/deploy. |
| Origin secret | The service is also reachable at `*.onrender.com`, which bypasses Cloudflare Access. With `ASTRQ_API__ORIGIN_SECRET` set, only requests carrying the header Cloudflare adds are served (except `/health`). |
| gzip + slower refresh | Render free egress is limited (5 GB/month). |

Known limits: 512 MB / 0.1 CPU (bursts like ATC may lag a few seconds); a restart mid-session
loses the raw ticks recorded before it (that day's baseline summary is partial); keep-alive
pinging is not explicitly addressed by Render's docs. Docker image build was not tested
locally (no Docker on the dev machine) — the Image workflow in astrq-platform-api builds it.

## 1. GitHub (organization + three repos)

The platform is three repos in one GitHub organization, cloned side by side:
`astrq-platform-api` (backend, Dockerfile, Image workflow), `astrq-platform-ui`
(dashboard, released as `ui-dist.tar.gz`), `infrastructure` (this repo).

1. In astrq-platform-ui: tag `v<package.json version>` on `main` → the Release workflow
   publishes `ui-dist.tar.gz`. astrq-platform-api's `ui.version` must name that tag.
2. In astrq-platform-api: merging to `main` runs the **Image** workflow, which pushes
   `ghcr.io/<org>/astrq-platform-api:sha-<commit>` and `:latest`.
3. GHCR package visibility: org → Packages → `astrq-platform-api` → Package settings →
   make it **public** (or give Render a registry credential, see `render.yaml`).

`.env`, `data/`, `.tunnel/` are git-ignored — your DNSE key never leaves your machine via git.

## 2. Cloudflare R2 (storage)

1. Cloudflare dashboard → **R2 Object Storage** → enable (free 10 GB; a payment method may be
   requested for verification) → **Create bucket** `astrq-radar`.
2. R2 → **Manage API tokens** → **Create API token** → permission *Object Read & Write*,
   scope: bucket `astrq-radar`. Copy **Access Key ID**, **Secret Access Key** and the
   **S3 endpoint** `https://<account_id>.r2.cloudflarestorage.com`.

## 3. Render

1. render.com → New → **Blueprint** → select the **infrastructure** repo (it reads
   `render.yaml`; the service is image-backed, Render builds nothing).
2. Fill the secrets it asks for:
   `ASTRQ_PROVIDER__DNSE__API_KEY`, `ASTRQ_PROVIDER__DNSE__API_SECRET`,
   `ASTRQ_STORAGE__REMOTE__ENDPOINT`, `ASTRQ_STORAGE__REMOTE__ACCESS_KEY_ID`,
   `ASTRQ_STORAGE__REMOTE__SECRET_ACCESS_KEY`.
   `ASTRQ_API__ORIGIN_SECRET` is generated by Render — open it later (Environment tab) and
   copy its value for section 4.
3. Service → Settings → **Deploy Hook** → copy the URL, and add it to astrq-platform-api
   as the repository secret `RENDER_DEPLOY_HOOK_URL`. From then on every merge to `main`
   deploys the image it just built. Rollback: Render → Manual Deploy → an older
   `sha-<commit>` image tag.
4. Wait for the first deploy; `https://astrq-api.onrender.com/health` must return
   `{"status":"ok"}` while every other path returns `403 Forbidden` (origin secret works).
5. Settings → **Custom Domains** → add `radar.astrq.io.vn`; Render shows the CNAME target.

### Moving from the single-repo service (astrq-radar) without downtime

1. Create the new `astrq-api` service as above, next to the old `astrq-radar`. Until the
   switch, run it on the demo feed so the two services never share the DNSE key or write
   the same R2 objects: override `ASTRQ_PROVIDER__KIND=synthetic`,
   `ASTRQ_CONTEXT__KIND=synthetic` and `ASTRQ_STORAGE__REMOTE__KIND=none`. Set
   `ASTRQ_API__ORIGIN_SECRET` by hand to the **same value** as the old service, so the
   Cloudflare header rule works for both.
2. Check `https://astrq-api.onrender.com/health` and the dashboard. After the session
   closes: suspend the old service, remove the three overrides on the new one (it now
   uses DNSE + R2 and restores the day from R2), then move `radar.astrq.io.vn` (Render
   custom domain + Cloudflare CNAME) to it.
3. Point the keep-alive Worker at the new URL (`TARGET_URL` in `wrangler.toml`, step 5).
4. Delete the old `astrq-radar` service once the new one has run a full session, and
   archive the old astrq-platform repo.

## 4. Cloudflare DNS, header rule, Access

1. **DNS** → add `CNAME radar → astrq-api.onrender.com`, **Proxied** (orange cloud).
   If `radar` already points to a tunnel from `scripts/tunnel-setup.sh` (astrq-platform-api), replace it.
   (If Render's domain verification stays pending while proxied, switch to DNS-only until
   verified, then back to Proxied.)
2. **Rules → Transform Rules → Modify Request Header** → Create:
   *When* hostname equals `radar.astrq.io.vn` → *Set static* header `X-Astrq-Origin` =
   the `ASTRQ_API__ORIGIN_SECRET` value from Render.
3. **Zero Trust → Access → Applications** → Self-hosted → `radar.astrq.io.vn` → policy
   *Allow*, include *Emails* = yours.

## 5. Keep-alive Worker

```bash
cd deploy/keepalive-worker
# edit wrangler.toml: TARGET_URL = your *.onrender.com URL
npx wrangler@3 login      # browser, once
npx wrangler@3 deploy
node test.mjs             # optional: window logic self-test
```

Open the Worker URL any time to see whether it would ping right now.

## 6. Abuse protection (recommended)

- Set `ASTRQ_API__ORIGIN_SECRET` + the Cloudflare transform rule (step 4): then only
  Cloudflare can reach the service and the visitor IP header it sends cannot be forged.
- `ASTRQ_API__TRUST_PROXY_HEADERS=true` (already in `render.yaml`) makes per-visitor rate
  limits work behind Render's proxy even without the origin secret.
- Cloudflare → Security → WAF → **Rate limiting rules**: `/api/` and `/ws`, 120 requests per
  10 s per IP → Block for 60 s. Security → Bots → **Bot Fight Mode** on.
- The app's own limits (`api.limits`) return `429`/`503` with `Retry-After`; see the README.

## Daily behaviour

- 08:50 first ping wakes Render (~1 min cold start) → connects to DNSE before ATO.
- Every 10 min until 15:10; the 15:05 job writes the EOD summary and uploads it to R2.
- ~15:25 Render sleeps. Opening the dashboard after hours wakes it (~1 min) and shows the
  day's signals restored from R2 (no live data until the next session). Earlier sessions
  (within `retention_days`) can be reopened from the date picker: their signals and
  end-of-day archive are fetched from R2 on demand.
